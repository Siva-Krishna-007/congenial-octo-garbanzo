LLM context length (Ollama only)

Ollama defaults to a small context window (commonly 2–4K tokens) regardless of what the underlying model actually supports, silently truncating anything beyond it — the usual cause of a local model "forgetting" earlier parts of a long document or conversation. This setting raises that cap for every Ollama call this app makes (Ask AI, Send to AI, question generation, proposal generation, AI edit).

Only applies when the chat provider is set to Ollama in Setup. Cloud models via OpenRouter manage their own context window server-side — there's nothing to configure or cap here, and this setting is ignored entirely for them.

Larger values need more RAM/VRAM and can slow down responses. A few starting points: 4096 for short Q&A, 8192–16384 for document analysis (matches most of what this app sends per call), 32768+ only if your model and hardware genuinely support it. Leave blank to use whatever the model/Ollama defaults to.

Compatibility note: this is passed as a top-level num_ctx field alongside the normal OpenAI-compatible request. Ollama's official documentation states its OpenAI-compatibility layer doesn't support setting context length this way (the documented alternative is baking it into a custom Modelfile) — recent Ollama versions may honor it as an extension regardless; unrecognized fields are otherwise harmlessly ignored. If it doesn't seem to be taking effect, updating Ollama is worth trying first.
